1) المشكلة اللي اتصممت الـ Generics عشانها

قبل C# 2.0 (سنة 2005) لو عايز collection تحط فيها أي نوع، مفيش غير object. ومن هنا ظهرت مشكلتين:

المشكلة الأولى: Casting وأخطاء وقت التشغيل

var list = new ArrayList();
list.Add(10);
list.Add("twenty");                    // الـ compiler مرّرها
int sum = 0;
foreach (int x in list) sum += x;      // InvalidCastException في الإنتاج

المشكلة التانية: Boxing

int i = 10 (Stack)→ box →[object header | MethodTable | 10] (Heap)→reference في ArrayList

كل int بيتحط في object بيتعمل له allocation على الـ Heap (header ومؤشر للنوع وبعدين القيمة). وunbox بيعمل فحص نوع ونسخ. في loop فيه مليون عنصر معناها مليون object يجمعهم الـ GC.

var a = new ArrayList();  for (int i = 0; i < 1_000_000; i++) a.Add(i);    // مليون allocation
var b = new List<int>();  for (int i = 0; i < 1_000_000; i++) b.Add(i);    // array واحد من int

الحل البدائي كان إنك تكتب IntList و StringList وهكذا (تكرار)، والحل الأصلي هو الـ Generics.

2) الفكرة (سلايد 4 و 5)

الـ generic هو قالب فيه placeholder للنوع (T)، وبتحدد النوع الحقيقي وقت الاستخدام. ربط فوائد السلايد 5 بالسبب التقني:

الفائدةليه بتحصل (الميكانيزم)
Type SafetyList<int> نوع حقيقي، والـ compiler يفحص كل Add قبل التشغيل.
Reusabilityكود واحد، والـ CLR هو اللي بيولّد النسخ.
Performanceالـ JIT بيولّد كود مخصص لكل value type فيتخزن int مباشرة (لا boxing ولا casting).
Cleaner Codeمفيش (int) في كل مكان ومفيش classes متكررة.

تصحيح (سلايد 5): "Better Performance" صحيحة مع الـ value types بس. لو T من reference type مفيش boxing أصلاً، فالفايدة هناك type safety وإزالة الـ casts مش السرعة.

3) الميكانيزم: Reification والـ JIT

الـ compiler بيترجم Box<T> مرة واحدة لـ IL فيه placeholder. وقت التشغيل، الـ CLR بيعمل نوع حقيقي لكل تركيبة، والـ JIT بيقرر الكود:

  • Value types: لكل نوع منفصل كود JIT، لأن حجم int غير double غير أي struct. مفيش boxing لأن الكود يعرف النوع بالظبط.
  • Reference types: كلها عنوان بحجم واحد، فبتتشارك كود واحد (__Canon) مع بحث بسيط عن الـ type وقت التشغيل لو احتاج (typeof(T)).

النوع وقت التشغيلموجود: typeof(T)اتمسح (بيبقى Object)مفيش، اتوسع نصياً
Value typesبدون boxingلازم boxing (Integer)بدون boxing
الفحصconstraints صريحةboundsوقت التوسع فقط (رسائل خطأ معقدة)
حجم الكودنسخة لكل value typeنسخة واحدةنسخة لكل استخدام

تكلفة مخفية: نسخة JIT لكل value type معناها وقت startup وذاكرة كود زيادة. تطبيق بيستخدم Dictionary<K,V> بعشرات تركيبات structs هيحس بيها. وفي NativeAOT التركيبات اللي مبتتحددش وقت الـ compile بتبقى مشكلة (خصوصاً مع Reflection).

4) Generic Classes (سلايد 6 إلى 8)

public class Box<T>
{
    public T Value { get; set; }
    public Box(T value) => Value = value;
    public void Show() => Console.WriteLine($"Value: {Value}");
}

var i = new Box<int>(123);
var s = new Box<string>("Hi");
var d = new Box<double>(3.14);

public class Pair<TFirst, TSecond>                 // أكتر من type parameter
{
    public TFirst First { get; set; }
    public TSecond Second { get; set; }
    public Pair(TFirst f, TSecond s) { First = f; Second = s; }
}
var p = new Pair<int, string>(1, "One");

المصطلحات

  • Box<> (open): مينفعش تعمل منه object. typeof(Box<>) بس.
  • Box<int> (closed/constructed): ده اللي بيتعمل منه objects.
  • تقدر تعمل Pair بـ Pair<int,int> مع تكرار النوع، والترتيب مهم: Pair<int,string> غير Pair<string,int> (نوعين مختلفين، وسلايد 11 سؤال 2).

إيه المسموح مع T من غير constraints؟

مسموحغير مسموح (وليه)
تخزين، تمرير، default، typeof(T)، ToString() و Equals (من object)new T() (مفيش ضمان إن فيه constructor)
المقارنة بـ null (دايماً false للـ value types)a > b أو a + b (مفيش ضمان للعملية)
تحويل لـ objectاستدعاء أعضاء النوع (t.Name)

باگ حقيقي: static لكل closed type

public abstract class Entity<T> { private static int _next = 1; public int Id { get; } = _next++; }
class User : Entity<User> { }  class Order : Entity<Order> { }
Console.WriteLine($"{new User().Id} {new Order().Id}");    // 1 1  (مش 1 2)

كل closed type له static fields و static constructor خاصين. لو عايز counter موحد حطه في class غير generic.

قيد مهم: مينفعش تعمل List<Box<?>> (wildcard زي Java). لو عايز collection لأنواع مختلفة من Box<T> اعمل interface غير generic (IBox) يرثه Box<T>.

5) Generic Methods (سلايد 9 إلى 12)

public static T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) > 0 ? a : b;

Console.WriteLine(Max(10, 20));             // 20  (T = int مستنتج)
Console.WriteLine(Max(7.1, 3.2));           // 7.1
Console.WriteLine(Max("apple", "banana"));  // banana
Console.WriteLine(Max<long>(5, 9));         // تحديد صريح
  • الـ method ممكن تكون generic داخل class عادية، ولها type parameters مستقلة عن الـ class.
  • Type inference: الـ compiler بيستنتج T من arguments بس، مش من الـ return type ولا من الـ var على الشمال.
  • كل استدعاء بنوع مختلف بيعمل closed method مختلفة (سلايد 10 "Each call can use a different type").
static T Create<T>() where T : new() => new T();
// var x = Create();             // خطأ: مفيش argument يستنتج منه
var x = Create<List<int>>();     // لازم تحدد النوع

static void Swap<T>(ref T a, ref T b) { (a, b) = (b, a); }
int p = 1, q = 2;  Swap(ref p, ref q);    // p=2, q=1 (T=int مستنتج، ومن غير boxing)

إمتى تحتاجها؟ دوال مساعدة: Retry<T>(Func<Task<T>>)، Map<TIn,TOut>، Deserialize<T>(json)، GetService<T>(). وفي Swap مثلاً بتتجنب كتابة نسخة لكل نوع.

6) Generic Interfaces (سلايد 13 إلى 15)

public interface IRepository<T>
{
    void Add(T item);
    T? Get(int id);
    List<T> GetAll();
}

public class ProductRepository : IRepository<Product>       // closed: Product ثابت
{
    private readonly List<Product> _products = new();
    public void Add(Product p) => _products.Add(p);
    public Product? Get(int id) => _products.Find(p => p.Id == id);
    public List<Product> GetAll() => _products;
}

public class InMemoryRepository<T> : IRepository<T> where T : class   // open: يفضل generic
{ /* ... */ }

السلايد بيقول "any class that implements it must specify the type arguments": يا إما تحددها (: IRepository<Product>) أو تمررها (: IRepository<T>).

// class واحدة تنفذ نفس الـ generic interface بأنواع مختلفة (CQRS handlers)
public interface IHandler<in TMsg> { Task HandleAsync(TMsg msg); }
public class OrderHandlers : IHandler<OrderCreated>, IHandler<OrderCancelled>
{
    public Task HandleAsync(OrderCreated m)   => Task.CompletedTask;
    public Task HandleAsync(OrderCancelled m) => Task.CompletedTask;
}

// تسجيل open generic في DI: سطر واحد لكل الـ entities
services.AddScoped(typeof(IRepository<>), typeof(InMemoryRepository<>));

أسماء الـ type parameters (سلايد 15): T نوع عام، TKey و TValue، TResult، TEntity، TId، TSource. وبتبدأ بـ T دايماً. ومع أكتر من واحد استخدم أسماء توضح الدور.

أمثلة تلاقيها كل يوم: IEnumerable<T>، IComparable<T>، IEquatable<T>، ILogger<T>، IOptions<T>، Task<T>.
